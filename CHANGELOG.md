# Changelog

All notable changes to Graph Shipper are documented here.

## [Unreleased]

### Added

- Project Contracts may declare `delivery.commitIdentity` as a non-secret Git name and email used by every commit and rebase the runtime creates. The field defaults to `Graph Shipper <graph-shipper@localhost.invalid>` when omitted, preserving existing contract behavior, and validation refuses malformed email, control characters, angle brackets, and whitespace Git would normalize. Repository identity hooks can therefore accept an `open_pr` branch without an operator rewriting its history by hand.

- Existing-file changes are now agent-authored, base-bound `edit_file` actions instead of whole-file `write_file` replacements. Plans must declare `fileActionSemantics: "base_bound_v1"`, so older overwrite-shaped fixtures and provider responses fail schema. Repository evidence carries each file's SHA-256; the Build Provider copies it and supplies exact old/new text replacements. Before persisting the plan or creating any effect, the runtime validates the entire action batch: `write_file` targets must be absent, edit targets must match the full base digest, every old-text anchor must occur exactly once, ranges may not overlap, duplicate targets and invalid observation commands are refused, activated `write_file` policy and protected-path rules apply to both mutations, and provider-produced contents receive credential screening. The runtime materializes final bytes for every action before the first effect and carries exact absent/base-digest preconditions into the existing `file_write` lease/intent/receipt path, preserving apply-before-receipt recovery without rematching a partially changed file. No human supplies file contents or repairs, and no shrinkage heuristic, fuzzy patch, generic model tool, new contract action kind, or overwrite compatibility escape hatch exists.
- A Work Item may declare an ordered exact-path `repositoryContextManifest` that narrows the activated Project Contract's repository-context globs for planning. This closes the large-repository failure where the tool-free planner received the first lexicographic 1 MiB instead of the human-selected runbook, source, and tests. Existing requests keep the prior contract-wide behavior when the field is omitted. Explicit manifests are all-or-nothing: paths must be canonical, unique, tracked, contract-admitted, regular non-symlink UTF-8 files with no credential-like content; individual files above 128 KiB or selections above 1 MiB fail before model dispatch rather than silently disappearing or truncating. The independent reviewer remains scoped to the complete exact-head diff, changed files, and canonical living documentation, so planner selection cannot weaken review evidence.
- A Project Contract may declare `workspace.preparationCommandRefs`: ordered commands run once in the fresh owned worktree before any gate. Without them the earned deterministic gate — the runtime's central claim — was only available to projects whose test command resolves nothing, because a `git worktree add` installs nothing and there was no contract language that could. The worktree is a sibling of the repository rather than a descendant, so Node's upward `node_modules` walk never reaches the primary clone's install, and the same shape holds for any language with a project-local dependency directory. The gap stayed invisible because every fixture and the canary project is a single-file script with no dependencies. Declaring the install as a gate was closed off by design (a gate must be pure, side-effect-free, and credential-free), and placing the worktree under the repository was closed off too. Preparation is therefore its own phase with its own effect class: each command runs under its own Effect Intent and Receipt, so a resume adopts the installs that completed and re-drives only the one with no receipt, which its declared idempotence is the permission for. Each referenced command must be credential-free, idempotent, declare `sideEffect: workspace`, run in the worktree, and take no parameters; a duplicate reference is refused, because the second would resolve the first's effect id and silently no-op. A monorepo declares one command per dependency tree — the first real contract authored against an outside repository needed two. The phase then proves the worktree still carries no tracked changes: whatever an install writes has to be ignored by the project's own `.gitignore`, no contract-time check can know that because it is a fact about the repository rather than the contract, and the alternative was a `workspace_drift` escalation on every run with nothing naming the install as the cause. A failed install stops the run before planning and retains the worktree; its output is not carried into the failure, since a package manager reporting a registry rejection is exactly where a credential would surface. Contracts declaring no preparation are unaffected, phase-for-phase.
- Declared commands now receive a usable environment instead of `PATH` alone, so a project's real toolchain executes rather than merely validating. The runtime provides a private `HOME` and `TMPDIR` under the data root: the home is per project, so a package-manager cache survives between Work Runs, and the temporary directory is per run, so nothing leaks across them. Neither is the operator's, and neither is inside a target repository. A command may additionally declare an `environmentPasslist` of variable NAMES; values are read from the operator environment at execution time and never persisted. The passlist admits by name from a small runtime-owned set — locale and terminal shape, proxy endpoints, TLS trust roots, and non-authenticating package-manager settings — rather than excluding a denylist, because a denylist over credential names cannot win: `GH_PAT` carries a token, `NPM_CONFIG_USERCONFIG` and `KUBECONFIG` name a file holding one, `DATABASE_URL` embeds one, and `NODE_OPTIONS` or `LD_PRELOAD` inject code into a digest-verified child. Runtime-owned names are refused in any case spelling, since Windows folds them together. The passlist therefore cannot become a second credential channel bypassing the Credential Broker. An earned `npm test` gate now runs to a green deterministic verdict through the runtime.

- Live GitHub transport behind the conspicuous `--allow-live-github-mutations` opt-in, symmetric with `--allow-credentialed-model-calls`. `RecordedGitHubTransport` is no longer the only implementation: an authenticated HTTPS transport resolves the contract's `github_operator` credential reference through the Credential Broker at the adapter boundary, pushes the exact leased head with remote compare-and-swap and read-back verification, and waits for hosted evidence with bounded exponential backoff inside the Work Run deadline. Rate limit, auth, 5xx, and network failures normalize to provider-neutral classes that carry a status class and no response body. The fixture and the live transport are mutually exclusive; `open_pr` and `merge_when_green` with neither still fail closed, `local_only` accepts neither, and no test calls GitHub. A live `merge_when_green` requires a second `--allow-live-merge`, so the authorization that reaches a real merge and a real local-main reset is never the one that merely opens a PR; the fixture path keeps requiring `--allow-disposable-fixture-reconciliation`.
- Live Post-Merge Hooks require their own `--allow-live-operational-hooks` rather than the fixture-scoped `--allow-disposable-fixture-operations`, and either live flag without `--allow-live-github-mutations` is refused rather than silently inert.
- Local-main synchronization fetches the forge-side merge commit into the primary clone before proving it exists, so a live merge no longer lands on the forge and then dead-ends on a commit the clone has never seen.
- Base refresh obtains an advanced remote base through the same credentialed fetch, so a base that moves mid-run is rebased onto rather than failing permanently for lack of the commit. Only a fast-forward of the primary clone's default branch is taken, under the preconditions local-main synchronization already enforces: a clone that is dirty, off the default branch, whose HEAD disagrees with the branch name git resolved, or carrying work the remote base does not contain still fails closed with the reason named, because resetting an operator's own commits away is not the runtime's to do.
- List reads follow `Link: rel="next"` to the end of the list, so a pull request with more than a hundred comments can no longer make the runtime publish a duplicate review verdict, and more than a hundred check runs can no longer read as missing required checks. `GitHubTransportResponse` carries the pagination link for this and nothing else; a transport that answers a list completely in one body may omit it. Paging is bounded at ten pages. The check-runs envelope reports a `total_count`, which is still cross-checked against what arrived so a shortfall fails closed; the other four endpoints report no count, so their completeness rests on the transport supplying the pagination link.
- Idempotent reads retry rate-limit and 5xx failures inside the Work Run deadline, honoring `retry-after`; mutations are never retried. Request timeouts clamp to the remaining wall-clock budget, observation backoff resets when the caller observes progress, and a push that could not run at all is reported distinctly from a rejected lease.
- A forbidden GitHub *read* is passed through to the typed adapter rather than raised as a fatal authentication failure, so a token without branch-protection visibility makes the merge guard report an ineligible base instead of aborting the run with a misleading credential error. A forbidden *write* stays fatal. The request deadline now spans the response body rather than only its headers, the exact-head `git push` is bounded by its own timeout, normalized failures release the response body, and credential material is scrubbed from transport error details.
- An open pull request is adopted on branch identity, with head exactness asserted separately against the single-object read. The list read can lag the ref it describes, and the branch may carry only one open pull request, so falling through to a second `POST /pulls` produced a 422 rather than a recovery.
- A recorded fixture's local commit source resolves against the fixture file rather than the invoking directory, so a relative path names the same repository wherever the CLI was run from.
- Model transport failures scrub credential material from their details. The scrubber is captured inside the credential scope, because disposal releases the redactor registration before the failure is reported.
- A passlisted environment value carrying userinfo in an endpoint is refused before the command runs. The passlist admits by name, and a proxy endpoint is legitimately admissible, so the name-based screen cannot see `https://user:token@proxy.internal` — and values are deliberately never persisted, so the redactor never sees it either. The refusal names the variable and not the value. It applies to endpoint-valued names only: an `@` in `SSL_CERT_FILE` is a filename, and one rule asked to read `operator:tok@squid` as a host and `certs@2024` as a path has to be wrong about one of them. Knowing which reading applies makes both exact, so a portless single label and a percent-encoded host are refused in an endpoint and ignored in a path. Every declared command's passlist is also swept against the ambient environment at Work Run construction, so a typo fails the run before any outward mutation rather than at the Post-Merge Hook that discovers it after a merge has landed. The execution-time check stays authoritative, because the environment can change while a run does. The sweep gates `resume` as well; nothing durable is touched before it, so a run refused there resumes once the operator clears the variable it names.
- A crash inside base refresh resumes instead of stranding the Work Run. `refresh_base` was not a reconcilable kind, so a crash between preparing the effect and completing it made every later `resume` refuse the prepared effect outright. Both halves of a refresh are observable, so the window now resolves by looking, and either way the evidence a base advance invalidates is cleared. A worktree on this run's branch carrying this run's trailer and descending from the advanced base is adopted — an interrupted rebase leaves a clean tree too, so descent alone would adopt a partly-rebased branch. A worktree still on its previous head records a failed attempt and lets the merge guard drive a fresh one. A head that is neither is refused as unattributable, and an intent this build cannot read is refused rather than reconciled from nothing.
- Every completed Work Run reclaims its own per-run temporary root, not only `merge_when_green`. The directory is created the moment a declared command runs, but only `merge_when_green` reaches the cleanup phase, so `local_only` and `open_pr` — the autonomies expected to run most often — left one behind each time. The reclaim is the same ownership check, at the same point, and it is recorded in the run's own evidence so an audit can still answer what a run deleted. A run that paused or failed keeps its temporary root, so a resume still finds what its commands left behind. The check now covers the whole path rather than only its last component, so an ancestor that leaves the data root through a symlink is refused.
- The test suite is bounded by `--test-timeout`, and all three tests that spawn the CLI subscribe to its exit before racing it. A listener attached after the race waits for an event already past, and with no timeout that is a hang rather than a failure.
- The plan schema is rewritten into the subset OpenAI structured outputs accept, so an OpenAI Build Provider can plan at all. A live canary found it could not: the schema OpenAI refuses is the one a discriminated union compiles to, and it was refused at dispatch on both the API and the subscription transport, which is why an OpenAI *reviewer* worked while an OpenAI *builder* never had. Every test injects the transport, so no test could reach it. The root union collapses into one object whose variant-specific properties are nullable and required, nested `oneOf` becomes the `anyOf` OpenAI does accept, and the keywords it refuses are dropped; the nulls a required-everything object forces are removed from the response at every depth before the real schema runs, which still rejects anything the loosened schema let through. A construct with no expression in the subset is refused where it is built, naming itself, rather than at dispatch as a provider error. Anthropic keeps its own schema unchanged.

### Changed

- `open_pr` now publishes the already-approved opposite-provider verdict as a durable exact-head provider attestation and may complete without a second human GitHub review. Publication is a separately leased, idempotent issue-comment effect bound to the run, head, provider, and Review Bundle digest; apply-before-receipt recovery adopts the same canonical comment rather than posting twice. Hosted observation requires the recorded comment ID and byte-exact body to remain present, so PR-body text, generic comments, stale-head publications, and edited or deleted attestations cannot satisfy the terminal. Trusted native GitHub reviews remain an alternative open-PR approval and the only review signal used by merge eligibility; `open_pr` still receives no merge, base-refresh, local-main synchronization, source-closure, cleanup, or operational-hook authority.

- `open_pr` no longer calls GitHub's Checks API when the Project Contract declares no required hosted checks. The empty requirement remains vacuously green while exact-head review and trusted-feedback observation still run, so a least-privilege GitHub operator token needs Checks read permission only when the human-authored contract names a check. The first live canary found the previous unconditional read after its scoped token had already pushed the exact branch and opened the PR.

- Owned-worktree cleanliness decisions no longer trust writable ignore rules. Resume reconciliation refuses unattributable output hidden by shared `info/exclude`, repository-local `core.excludesFile`, or an uncommitted `.gitignore`, while preserving attributable visible state. Act-phase attribution force-stages exact planned paths hidden only by those rules and refuses hidden paths the plan does not own. Delivery-terminal cleanup records at most twenty path/rule findings plus the exact total count in its effect and evidence, rejects malformed persisted finding metadata, and still reclaims the exact owned worktree after terminal and ownership proof; repository bytes remain outside runtime persistence.
- Workspace preparation now asks Git to render the pinned base's tracked blobs through checkout filters in memory, then compares those expected bytes and modes to the worktree without passing observed bytes through clean filters. The proof trusts neither the owned worktree's index flags nor its stat cache, so `assume-unchanged`, `skip-worktree`, sparse-checkout state, a forged clean stat entry, and a rewrite that clean filters would normalize cannot hide tracked drift; a legitimate filter-rendered checkout still passes. Suppressing index bits are refused even when bytes still match because a fresh owned worktree inherits neither one, while repository-local configuration and shared `info/attributes` are bound before preparation. No tracked bytes or proof-created blobs cross into runtime persistence, and the comparison remains bounded to base-tracked paths rather than installed dependency trees.
- Declared pure gates now compare an exclusion-blind snapshot of untracked path identity and change metadata around command execution, and bind the shared `.git/info/exclude` digest separately. A gate therefore cannot earn green deterministic evidence after hiding a new artifact through shared excludes or an uncommitted `.gitignore`, rewriting an existing ignored preparation artifact in place, or poisoning the shared exclude file itself. The check remains a gate-local delta and does not change resume, cleanup, or act-phase attribution.
- Workspace preparation no longer trusts an ignore rule the install being checked could have written. The phase proves the owned worktree carries no tracked changes after the last install, and that probe asks the ignore rules. Three of them are writable during the phase: the shared `.git/info/exclude`, which lives in the primary clone's Git directory a linked worktree shares; a repository-local `core.excludesFile`; and a `.gitignore` the command wrote and did not commit, which is the cheapest of the three because it needs no shared Git metadata at all and can cover itself with one `*`. An install could write any of them and earn a clean preparation receipt for output nobody declared, and a dependency's `postinstall` can do the same, which is code the reviewed argv does not describe. The phase now asks which rule decided each leftover file rather than whether an exclude file carries a pattern. `git ls-files --others` applies no ignore rules, so every untracked file is listed whatever hid it from status, and `git check-ignore -v` names the deciding rule; only a tracked `.gitignore` is a rule the contract digest reaches, and the caller has already proven no tracked file was modified, so tracked means identical to the base revision. `core.excludesFile` is neutralized on that probe rather than in the shared Git configuration, because this probe must not honor a setting that can promote a tracked `.gitignore` to a global exclude, while authorization-source eligibility must honor it to keep refusing a source the project's own ignores hide. Both probes read every path they are given as a pathspec rather than a pathname, which is the trap the mechanism turns on: `check-ignore` refuses the literal magic that would turn that off, so a path opening with the `:` sigil is refused unprobed rather than resolved against a different path and attributed to that path's rule, and the trackedness probe takes `--literal-pathspecs`, without which a directory named `*` borrows any nested tracked `.gitignore`. Files are enumerated one per file rather than collapsed per directory, so a committed `*.log` covers `logs/install.log` wherever the install puts it, and an empty directory that Git never reports and a project cannot commit costs nothing. An enumeration that warns about a directory it could not read fails rather than proceeding on a short list, because an install can hide a tree by chmodding the directory it wrote and `ls-files` reports that omission only as a warning on a zero exit. What the phase proves is bounded by what Git enumerates, which does not include a directory named `.git` at any depth. A refusal names the file and the rule that hid it, capped at twenty. Contracts declaring no preparation are unaffected.

- `status` reports an activation whose contract the validator now refuses, rather than throwing. It validated first and threw on failure, before reading the activation, so the moment validation learned a new refusal every activation bound to a contract of that shape became uninspectable by the one read-only command an operator has for asking why a run was refused. A schema-parsed invalid contract is looked up only when its project ID and canonical root match the activation's own immutable root; a copied or moved clone cannot inherit or disclose the original root's activation, and later onboarding at the new root cannot move it. Explicit human activation is the only operation that binds authority to the new root. Legacy activations that predate the stored root fail closed and require reactivation rather than inheriting mutable project state. An invalid contract at the activated root is reported `stale`, never `current`, because admission evidence is computed from the parsed contract and an invalid one has none to compare against. The exit code stays `3` and the same `ok: false`, error, details, and status report are written with or without `--json`; the plain path also writes the failure to stderr. A contract that names no project, being unreadable or not YAML, still throws, since there is nothing to look up.
- A verification check declaring a `builtin` executor is refused at `contract validate`, and the shipped template no longer declares one. No builtin verifier is implemented, so the template's `kind: builtin` check validated, onboarded, activated, and then failed at the first Work Run. The schema still admits the variant, so a future builtin has a name to arrive under and a contract naming one hears why it is refused rather than failing as an unknown discriminator. The template now declares its gate as a command, which is the only shape a Work Run executes. Validation also refuses an approval policy that provably cannot authorize a write: no effective `pre_approved` rule covering `write_file`, including the case where every such rule has empty `pathGlobs`, or a `forbidden` rule whose compiled glob covers every project-relative path. An inert empty-glob rule beside a working grant remains valid. The policy is forbidden by default and the template ships `rules: []`, so a run authored from it was refused at its first planned write, the same surprise one phase later. Provably is the limit: whether a planner's paths fall inside narrower declared globs is not knowable at validation, so a policy can pass here and still deny a write. The template keeps `rules: []`, because which paths a run may edit is the project's decision; it carries a commented example that uncomments into a valid rule, and validation names the omission. Policy validation now enumerates the runtime's consumers: `effect: consequential`, `read_only` applied to `write_file`, unknown action kinds, command rules carrying ignored `pathGlobs`, and `PolicyRule.argvPrefix` are refused instead of silently narrowing nothing. `repository.primaryCloneRealpath` must resolve to the project being validated; left as the template's placeholder it validated and then escaped onboarding as a raw `ENOENT` carrying the usage text. Authorization-source eligibility uses the shared scrubbed Git configuration, rejects non-repositories, repository-owned ignores, and nested repositories, and reports a missing or failed Git probe instead of treating it as permission. Operator-global excludes remain deliberately scrubbed, and onboarding still refuses the resulting untracked source. Every source path must also traverse no symlink at all, including a symlink that resolves back inside the project. A test takes a contract authored from the template, with its placeholders filled and one pre-approval rule declared, through onboarding, activation, and a `local_only` Work Run to completion. The run-time refusal remains a fail-closed backstop. Validation also refuses a command whose authorization sources the project does not hold: the closure walk skips a source it cannot read, so a contract naming a script nobody has written yet used to validate cleanly and fail two steps later at onboarding, which is exactly the shape the template hands a human.
- A planned `run_command` action carries its parameters as named pairs rather than a free-form map, which has no expression in the OpenAI subset. One portable wire format beats a per-provider rewrite of the response, so a recorded adapter fixture written against the map form has to be restated. A list can state a name twice where a map could not, so a repeat is refused rather than silently resolved, and the list carries no default: a planner states it, because a missing property has to read as missing.
- Admit human-approved executables for project commands. A contract may declare an `executableAllowlist` of exact argv prefixes, resolved at Binding Admission, so a project can name its real toolchain — an earned `npm test` gate, `npm install` Post-Merge Hooks, or its own merge coordinator. Previously every command required `argv[0] === "node"` and command scripts could import only a 16-module builtin allowlist excluding `node:child_process`, so no real project lifecycle was expressible. Prefix pinning is strict: admitting `npm run test` admits that script alone, never `npm run <anything>`. Wrapper executables and interpreter eval modes stay refused even when a contract names them explicitly, and allowlist entries are themselves validated so a wrapper cannot enter as one. Static import-closure inspection is unchanged for Node script commands.
- Allow project-coordinator delivery commands to run from the project root and declare a `github` side effect, so a project whose coordinator genuinely mutates the forge can say so instead of mislabelling it. They stay credential-free and the runtime brokers them nothing. The limit noted here when that landed — declared commands receiving only `PATH` — is lifted by the runtime-owned home and environment passlist above.

## [0.4.0] - 2026-08-16

### Changed

- Make ordered, deadline-bounded Post-Merge Hooks part of the merge terminal predicate; source closure and owned cleanup now wait for every contract-declared observable success/smoke probe.
- Preserve explicit merged truth and non-terminal source state when hook retries or compensation are exhausted or ambiguous; compensation never converts a Work Run to shipped.
- Widen the recoverable Work Run through `merge_when_green` for projects with no operational Post-Merge Hooks; completion now requires Delivery Strategy terminal proof, local-main synchronization, applicable source closure, and ownership-checked cleanup.
- Invalidate and regenerate deterministic, documentation, hosted, review, and publication evidence when the exact base advances before merge dispatch.
- Widen the recoverable Work Run through the `open_pr` authority envelope while keeping merge and Post-Merge Hooks unavailable.
- Re-run deterministic, documentation, opposite-provider review, and hosted evidence after every repaired head; exclude untrusted, stale-head, and scope-changing feedback from repair.
- Report PR, hosted, repair, source-revision, and escalation state explicitly through `status --run-id`.
- Fail Binding Admission when a non-idempotent Post-Merge Hook lacks a side-effect-free observable probe.
- Model Compensating Hooks as separate human-approved contract entries with captured prior state, exact literal targets, explicit ownership, timeout/retry policy, and success probes; reject repository targets and runtime-invented target parameters.
- Refuse to follow tracked Markdown symlinks during deterministic documentation analysis, including broken or external targets.
- Apply duplicate-anchor, fence, contradiction, and local-link checks to living/generated documentation only; historical and vendored/reference files remain cataloged and protected without creating unrelated repair work.
- Require model fallbacks to retain their primary assignment's transport, make API credential references conditional on API transport, and reject resume across Graph Shipper runtime revisions.

### Added

- Add per-project hook serialization, exact activated argv/working-directory execution, isolated per-command operational credentials, prior-state artifacts, timeout/backoff/retry, and durable hook/compensation effect reconciliation.
- Add harmless operational fixtures for ordered success, transient recovery, apply-before-receipt process death, successful compensation, exhausted compensation, and ambiguous compensation without a live project canary.
- Add durable per-project merge serialization, short-lived operation leases, opposite-provider verdict publication, exact branch-protection/base/head dispatch guards, and crash reconciliation for publication, coordinator enqueue, and merge.
- Add deterministic GitHub-direct and project-coordinator Delivery Strategy fixtures; coordinator selection never falls back to direct merge.
- Require an explicit disposable-fixture reconciliation flag before a fixture-backed merge run may synchronize or clean a target clone.
- Add an exported typed GitHub Adapter for compare-and-swap branch push, normal PR create/update/adoption, required checks, exact-head review, issue/review/inline feedback, and source-revision observation.
- Add an external-state deterministic GitHub transport with hosted waiting and crash fixtures for push and PR receipt gaps.
- Support schema-bound Anthropic and OpenAI model assignments through authenticated Claude and Codex subscription CLIs as an alternative to direct API-key transport.
- Isolate subscription invocations in private scratch directories with scrubbed environments, disabled tools/customizations, bounded process output/time, ephemeral sessions, and explicit transport identity in durable evidence.

## [0.3.0] - 2026-08-14

### Added

- Run the unchanged recoverable `local_only` topology with OpenAI build and Anthropic review as well as the original reciprocal assignment.
- Provide all four provider/role adapters over shared portable plan and verdict schemas, with an offline conformance suite for refusal, truncation, malformed output, timeout, rate limit, authentication, and transport failures.
- Support explicit same-role, same-provider fallback assignments after one malformed-output retry, including deterministic recorded failure/fallback fixtures.
- Record the selected build/review provider and model references, runtime version, exact evidence bindings, and provider-neutral failure events without persisting provider payloads.

### Changed

- Generalize repair dispositions, evidence, and CLI results from a hard-coded provider direction to the activated assignments while preserving opposite-provider review and fresh read-only review context.
- Normalize exhausted provider failures at the Work Run boundary so traces, checkpoints, status, and evidence retain the failure class without raw provider messages or credential material.

## [0.2.0] - 2026-08-14

### Added

- Ship the standalone Graph Shipper CLI with strict project-contract validation, evidence-bound local activation, private durable state, and read-only diagnostics.
- Run recoverable `local_only` Work Items in managed Git worktrees with revision-pinned intake, bounded Anthropic build and repair, deterministic and documentation gates, and independent OpenAI review.
- Resume safely across workspace, file, commit, gate, review, and final-evidence crash gaps while preserving the original base and escalating ambiguous state.
- Enforce broker-issued local authority leases, exact command shapes, digest-bound Node scripts, minimal child environments, pure-command postconditions, and persistence-wide credential redaction.
- Provide offline provider fixtures, public fault-injection seams, and end-to-end CLI coverage for normal, repair, policy, and recovery paths.

### Changed

- Replace executable blocklists with a positive local command boundary that rejects wrappers, interpreter evaluation, unsupported workspace strategies, and unsupported verifier variants before mutation.
- Bind review and documentation evidence to the exact contract, Work Item revision, base, head, gates, changed content, and finding-to-repair disposition.
- Bind every command entry/helper source into activation evidence, admit only an exact direct-Node command shape, and reject credential-like material in the contract-approved model-context allowlist.
- Make preserved `local_only` handoff ownership explicit and scope removal policy to later delivery-terminal success.
- Validate local import closure for every authorized command with a conservative tokenizer and positive built-in capability list that reject non-literal, bare-package, loader, process, VM/worker, and network execution paths; screen command evidence for credential signatures; and refuse symlink-redirected final evidence publication.
- Enforce the same command-source and built-in capability policy at module resolution time, while removing ambient Node loader and network globals before authorized code executes.
